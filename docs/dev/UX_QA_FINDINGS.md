- [ ] Open — attack next
	- [x] Escape cancelling inline edit: now bound at the CAPTURE phase as well as the bubble phase, so a global hotkey layer (AutoHotkey/PowerToys) swallowing the bubbling keydown can no longer cost the user their cancel. `finish` is idempotent, so both paths firing is harmless
	- [x] Diagram spacing — **measured, and the original diagnosis was wrong.** Rendered the real DOM against the real stylesheet in headless Chromium (`docs/dev/VISUAL_HARNESS.md`). Findings: (1) the canvas height is *leaf-bound* — it equals `leaves × (row + gap)`, so it is already optimal for this layout family; (2) `align-items` is irrelevant — centre and flex-start both produce **exactly 460px**, flex-start merely pools the whitespace at the bottom and made the worst sibling gap *worse* (98px → 116px); (3) only the row gap moves height at all (8px → 4px = 460 → 420). The perceived "gap" is a parent box centred against a tall subtree, which is inherent. A genuinely tighter tree needs contour-based packing (Reingold–Tilford), tracked as a v1.2 candidate. What shipped instead was the **opposite** of tightening — see the density pass below, which is what the view actually needed
	- [x] The tree views were cramped overall — shipped a spacing/hierarchy pass ("Canvas"): spacing tokens on `.tt-view`, roomier rows, indent guides in the list, diagram nodes as cards on a subtle dot-grid canvas, depth-aware type weight, and a status edge on diagram cards. The old dense packing is preserved as the **Compact** density setting
	- [x] Kanban: an empty column now renders a dashed "Drop a task here to mark it <Column>" target, hidden by CSS the moment the column holds a card (mid-drag included)
	- [x] "Mark as …" / "Move to …" menu entries now carry a per-role icon (todo `circle` · doing `play` · done `check` · cancelled `x` · blocked `ban`) instead of five identical checks
	- [x] Inline-edit input capped at `min(100%, 520px)` — it no longer stretches window-wide in the diagram/columns layouts
	- [x] Keyboard-only path — **closed**. Arrow navigation now covers all three layouts (list and diagram share one handler; columns get Miller semantics where → drills in and ← steps out), Enter edits in place, Space toggles done, Alt+arrows do move/indent/outdent, and the menu key (or Shift+F10) opens the context menu at the row. Plus an "Add a task to the open board" command that takes a hotkey
	- [x] Starter tasks and note headings are no longer hard-coded: both are settings (`newBoardStarterTasks`, `taskNoteSections`), parsed by `src/model/templates.ts`. An empty starter template is legal — the tree then shows an "Add the first task" state

- [x] Round 4 — the deep philosophy/UX audit (1.1.1). Six defects, all verified against the code before fixing:
	- [x] **The plugin wrote characters it could not read back.** `DEFAULT_COLUMNS` has no `-` or `!`, yet `canonicalStatusForRole` emits exactly those for cancelled/blocked and the contract *installed in the user's vault* tells agents to write them. Both read back as `doing`, so a cancelled child kept its milestone from **ever** reaching done. `roleForStatus` now honours the published table as a fallback after the board's own columns. Root cause: the whole test suite used a five-role fixture no user ships with — the suite validated the plugin we meant to build. Added conformance tests against `DEFAULT_COLUMNS`
	- [x] **"Build the boards index" destroyed files it didn't own.** The update lambda discarded existing content, and with an empty new-board folder the path resolves to `index.md` **at the vault root** — one of the most common MOC filenames in Obsidian. Bundle files now carry an ownership marker and the commands refuse to touch anything else. (The report claimed `log.md` had the same shape; measured, it does not — `appendLogEntry` preserves existing content. Guarded anyway, since writing into a stranger's `log.md` is still a surprise.)
	- [x] **Invisible live tap targets.** `.tt-row-btn` was `opacity: 0` with `cursor: pointer` and no `pointer-events: none`; `styles.css` has **zero `@media` queries** and the manifest claims mobile support. Delete was an invisible target. Hidden buttons no longer receive events, and `@media (hover: none)` makes them permanently visible on touch
	- [x] **Escape was recorded as a permanent "no".** `confirmModal`'s Cancel button never set `answered`, so dismissing and rejecting were indistinguishable — and the agent-setup caller persisted both as `agentInstructions: "off"` forever. It now reports `confirm` / `reject` / `dismiss`; only an explicit Cancel is remembered
	- [x] **"Next up" contradicted itself.** A dependency-held leaf appeared under *Next up* AND *Waiting on dependencies* in the same panel (reproducible with `t-qa` in `examples/`). Now excludes held leaves and leaves under an ancestor explicitly overridden to done/cancelled. Note: only the **override** counts, never a rolled-up role — roll-up lets children win over a parent's character, so a parent merely typed `[-]` with a live child legitimately reads `todo`
	- [x] **The ribbon converted files without asking.** It wrote `type: task-tree` into whatever note was open and then appended `^ids` to every checklist line — two unrequested mutations, one click, against `docs/00_VISION.md`'s "never surprise the human's files silently". The consent screen already existed and simply wasn't routed through. Also fixed: a note declaring a different `type:` used to get a success notice and a dead button
- [x] Round 4b — the subtraction (1.2.0). "Simplicity is complexity" is Tesler's law: complexity is conserved, only moved. The audit's verdict was that Task Tree routed too much of it to the user — and, because the target user works alongside an AI agent, to an audience with no eyes.
	- [x] **Settings 23 → 12.** The test applied to each: does it encode a genuine disagreement between two reasonable users (*where do my files live*), or a decision the plugin declined to make (*what does an unmapped character mean*)? The second kind is now `FROZEN` in `settings.ts`, with the answer the docs always published: `unknownRole: doing`, `blockedDominates: true`, `^t-` + 6 chars, tab indent. Also gone: `parentAutoSync` (**0 references anywhere in `src/` — shipped in every user's `data.json`, read by nothing**), `idPrefix`/`idLength`, `autoAssignIds` (ids are infrastructure; the toggle's only power was to break dependencies and collapse state), `maintainTimestamp` (its own description admitted it "adds churn to git"), `checkboxCycles` (a checkbox that lied about being a checkbox), `showTaskNoteLink` (the "on" value showed every title twice — it was the optional version of a bug fix)
	- [x] `loadSettings` now prunes unknown keys and rewrites once, so the removed settings actually leave `data.json` instead of sitting there looking like configuration
	- [x] **Commands 11 → 8.** Dropped `assign-ids` (advertised that the automatic path isn't trusted) and the `index.md` / `log.md` generators — a second artifact that could only drift from a vault an agent already enumerates by grepping `type: task-tree`, which is exactly what `managedBoards()` does. `writeBundleFile`, `buildIndexMd`, `appendLogEntry` and `relPath` went with them
	- [x] **Menu: one vocabulary.** The Kanban said "Move to Done" and the tree said "Mark as Done" for the identical action, so the product contradicted the user's mental model depending on which lens they stood in. Both say "Mark as". "Move to end" deleted (Move down, repeated), and `moveToEnd` with it
	- [x] Indentation is no longer a setting at all: `loadBoard` already **detects** the unit a file uses, so the setting only ever applied to a board with no nesting yet — and could disagree with the file it was editing
	- [ ] **Kept deliberately, against the report's advice:** the status chip (the checkbox has three visual states for five roles, and `data-role` is never applied to `.tt-row` — without the chip, todo/cancelled/blocked would render identically, in the very release that finally makes them reachable), `treeDensity` (density is genuine variance between users), and per-column `color`/`wipLimit` — the one cut with a real taste component, left for a separate decision
- [x] Round 4d — derived state stops being clickable (1.4.0). The audit found **three** write sites that produced `[tt-override:: done]` without ever saying the word "override": clicking a parent's checkbox, dragging a parent card between Kanban columns, and "Mark as Done" in the menu. `AGENTS.md:62` forbids agents from marking a parent done; the plugin was doing exactly that, on the most natural gesture in each view.
	- [x] A derived parent's checkbox is now a readout — clicking explains what it derives from and writes nothing. Parent cards are filtered out of the Kanban drag pool (kept visible, with progress and a "derived" tag, so the board still shows containment). The menu says **"Override to …"** for derived nodes and **"Mark as …"** for leaves, in both views
	- [x] The predicate is `isDerived` (`children.some(isTask)`), living next to `computeRollup` and matching it exactly — **not** `isLeaf`, which counts non-task bullets, so a task carrying a plain `- note` would have had its checkbox wrongly disabled. Pinned by a test
	- [x] Row noise: note-progress is worded ("8 in notes") and silent when finished — two adjacent `K/D` fractions in identical type, counting direct children vs. checklist items several notes away, was the row's worst ambiguity. ⚠ now appears only where the chip isn't already Blocked; with blocked surfacing to parents the whole ancestor chain already says so, and the one case ⚠ earns is an ancestor overridden to done that is *hiding* blocked work
	- [x] "Blocked" had four referents (a status char, a rolled-up parent, an unfinished dependency, "something below is blocked"). Dependencies now say **"waiting on"** everywhere — badge, menu, labels. The FIELD stays `tt-blocked-by`: it is the format, and renaming it would break every board on disk
- [x] Round 4e — one scope, one hiding gesture, collapsed by default (1.5.0). Roll-up computes, for every parent, the one number that answers "how is that going" — and then the view opened every branch and spent that signal before the user saw it. A 40-task project arrived as 40 rows, and the fraction on the parent was decoration.
	- [x] **A board opens two levels deep.** `FROZEN.openDepth: 2` — milestones and what's directly under them. Measured on the harness: the fixture list went **451px → 325px** of content, and the diagram **707px → 519px**, which is the difference between a board that fits a pane and one that doesn't. The bet the plan flagged as highest-variance is that this reads as "my tasks disappeared"; what answers it is that a folded parent keeps its chip *and* its fraction — "Visual language · Doing · 0/3" is a branch you can judge without opening — plus a fold-all/unfold-all button in the toolbar
	- [x] **Folding is tri-state, and that is not an implementation detail.** Once a depth default exists, "absent from the `collapsed` set" can no longer mean "open": a hand-opened branch would silently re-fold the next time the default applied. So an explicit choice, in *either* direction, outranks depth forever — `collapsed` **and** `expanded`, both persisted per board. The rule is pure (`src/model/folding.ts`), so the off-by-one is a test rather than something someone notices in a screenshot
	- [x] **Four hiding mechanisms became one.** Gone: the full-focus tab (`getLeaf("tab")` unconditionally, and `getDisplayText` returned the same string for each — five indistinguishable tabs), the Miller **Columns** layout (a zoom stack drawn sideways; the proof it was redundant is that `setFocus` had to *clear the drill path* so two hiding mechanisms wouldn't contradict each other), `columnPath`, `wireColumnsKeyboard`, the three-way layout switch, and the two near-identical focus menu items — now one "Focus on this branch"
	- [x] **Caught by the harness, not by review:** the diagram still tested `collapsed.has(id)` directly instead of going through `isCollapsed`, so it drew an open branch under a chevron pointing right — the icon read the depth default, the recursion didn't. One hiding gesture means one predicate; a test now fails on any raw fold-set read in `tree-view.ts`
	- [x] **Focus and the depth default were fighting.** Focus scopes the view to one node, but that node keeps its *board* depth — so focusing a task at depth 3 rendered the single row you asked for and hid everything under it. Depth is only meaningful relative to what you are looking at: `FoldState.baseDepth` is the view root's depth, and folding counts from there. (`prepareModel` also had to move ahead of `buildToolbar`, since the fold-all button now asks which way to point *before* the id map exists.)
	- [x] **And the instrument was lying in two places.** Two fixture parents carried no `K/D` (harmless when everything was expanded; a dead end the moment folding shipped) and the diagram's progress bar was hard-coded to `width:50%` regardless of the fraction printed beside it. Both fixed — a measuring instrument that disagrees with the thing it measures is worse than no instrument
- [x] Round 4f — the five roles become reachable (1.6.0). 1.1.1 fixed half of this: `roleForStatus` learned to *read* `[-]` and `[!]` via the published table. The other half sat unnoticed for four releases — the menu was built by iterating `model.columns`, so on a default board **"Mark as Cancelled" did not exist**. The README advertised cancelled, roll-up excluded it from the denominator, and the `CONTRACT.md` the plugin installs told agents to write it. The human's AI collaborator could produce a state the human could not.
	- [x] Menus are built from `boardLanes(columns, ALL_ROLES)` in **both** views. Columns are a layout; a board's lane configuration was never meant to decide which states its tasks are permitted to be in
	- [x] `blocked` (`!`) joins `DEFAULT_COLUMNS`; `cancelled` (`-`) deliberately does not — blocked work is *in* the flow and is the lane you most want to watch fill up, cancelled is out of it and a permanently empty column taxes every board for a state most never reach
	- [x] **Cancelled cards were landing in To Do.** The Kanban fell back to `columns[0]` for any role with no column, so work you had explicitly decided not to do came back as the top of your backlog. Both obvious fixes are wrong — a permanent lane taxes everyone, hiding the cards makes the plugin conceal what the file plainly says. A lane that exists exactly when it has something in it is neither
	- [x] Cancelled rows recede rather than reading as finished (done is an achievement; cancelled is withdrawn), and that treatment is precisely what earns cancelled the right to have no lane. Caught in the harness: the chip had faded *itself* since 1.1.1, back when it was the only signal, and the two mechanisms compounded into an unreadable label in both themes. The row carries the recession now; the chip carries the word
	- [x] **The starter template taught nothing.** `"First task / A subtask / Second task"` marked nothing, so `K/D` never rendered and every new user's first board omitted the one mechanism no competitor copies. One subtask now ships done — `1/2`, a half bar, a parent visibly not done. Starter lines may carry their own `[x]`, using the same syntax the board uses, so the template stays a setting rather than becoming a hard-coded English literal
	- [x] **The manifest was advertising the commodity.** It led with roll-up, which Task Genius (151k) and CardBoard (170k) also ship — and both *mutate the parent*, destroying the recomputability that makes it worth anything. After 1.3–1.5 the invariant is structurally true rather than documentationally true, so it is finally the thing we claim
	- [x] Drift caught in passing: `CONTRACT.md` still described `blockedDominates` as "toggleable" and `unknownRole` as a setting, both frozen back in 1.2.0 — a doc that lies to an agent is worse than no doc. Fixed in `docs/agent/CONTRACT.md` and the bundled skill copy in the same commit (a test pins them byte-identical)
- [x] Round 4g — the panel says why (1.7.0). The recurring request behind "add priorities" is *what should I do next*, and the panel had been answering it in document order since v0.2 while sitting on both signals that actually answer it. The market says the field itself is the wrong shape: the entire Eisenhower category on Obsidian is **3,762 downloads across 12 plugins**, mostly maintained — non-adoption, not abandonment — and every one needs an "unjudged" drawer, because rating your own work is the chore users skip. TaskLens, with no priority field at all, has 4.5× the downloads of priority-matrix. So: derive it.
	- [x] **`unblocks N` from `resolveEdges`.** Counted strictly — a waiter counts only when this task is the **last unreleased thing** it depends on, and waiters already done or cancelled don't count at all. "3 are waiting on you" when two would stay stuck behind something else is a promise the board can't keep, and a number that overstates is worse than no number. Verified against `examples/`: finishing *Copy* frees nothing, because *Announcement post* still waits on *Staging box*
	- [x] **`completes "X"` from `computeRollup`.** `progress` already excludes cancelled children from its denominator, so "one open leaf left" is just `total - done === 1` — and the remaining child is necessarily the branch we walked up from, so the cascade needs no extra bookkeeping. In `examples/`, *Pricing page* correctly reads **`completes 2 milestones`** (*Wireframes*, then *Design*)
	- [x] **The cascade stops at an override**, the same principle as the 1.1.1 exclusion rule but pointing the other way: an overridden node is not decided by its children, so finishing the leaf would *not* close it, and claiming otherwise would be the badge lying in the one place a human stated intent in visible ink. A non-task bullet stops it too — it isn't counted in its own parent's progress, so the chain genuinely dies there
	- [x] **In-flight work still sorts first, at any leverage.** Leverage orders *within* each tier. A "next up" list that talks you into dropping work you already loaded the context for, to open a new front, has exactly one failure mode and that is it. Pinned by a test where a `todo` with `unblocks 2` still ranks below a bare `doing`
	- [x] Ties keep document order for free — `Array.sort` is stable, so the file's own sequence remains the last word instead of a synthetic tiebreak
	- [x] **One line of rule, not eight badges.** The ordering is stated once above the list; a row with no leverage gets no badge, because the absence is information too. Same split as `collectNoteWork`/"N left": numbers in the model, phrasing in the view
